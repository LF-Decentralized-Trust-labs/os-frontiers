# Open Replenishment Framework (ORF)

## Abstract

Web3 ecosystems have built sophisticated mechanisms to *spend* treasury capital through governance referenda (**dOSPO**) and maintenance retainers (**OMF**). What remains underdeveloped is the **collection half**: how value created by sustained open-source infrastructure flows back to replenish the capital base that funded it.

The **Open Replenishment Framework (ORF)** introduces a portfolio of 20+ collection instruments organized into five primary layers: **Protocol, Application, Enterprise & Services, Capital, and Delegation**.

---

## 1. The Closed Sustainability Loop

```
[ Treasury Deploys Capital ] ──> [ Open Source Sustained ] ──> [ Risk Reduced & Adoption Grows ]
           ▲                                                                 │
           │                                                                 ▼
[ Capital Base Replenished ] <── [ Economic Value Collected ] <── [ Enterprise & User Activity ]
```

- **Deployment (dOSPO + OMF)**: Authorizes spending and manages maintenance retainers.
- **Collection (ORF)**: Matches collection instruments to where value is realized across protocol fees, app badges, enterprise SLAs, and treasury yield.

---

## 2. Four Core Governing Principles

1. **Value Alignment**: Collect at the exact point where value is realized (Protocol fees, App transactions, Enterprise SLAs, Treasury yield).
2. **Fork Resistance**: Attach capture to non-copyable assets (canonical state, liquidity, registry badges, SLAs) rather than software license restrictions.
3. **Benefit Bundling**: Sold, not taxed. Enterprise patch windows, SLAs, and registry badges offered while security intake remains free and universal.
4. **Mandate Governance**: Every collection rail carries a dOSPO mandate, time-limited charter, and independent audit review.
